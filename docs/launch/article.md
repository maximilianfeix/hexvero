# What changed in this Electron update? Reading two builds without running either

_Draft for DEV or a personal blog. Written with an AI assistant from the maintainer's notes;
rewrite it in your own words and disclose the assistance where the platform asks for it._

An Electron app ships as an `app.asar`: the main process, a preload script and a renderer bundle,
usually minified. When version 1.5.0 replaces 1.4.0, the questions a reviewer has are short:
can a web page now reach something it could not before, did a window lose its sandbox, does the
app talk to a new server? A diff of two minified bundles does not answer them, and running the
new build to find out is the thing you were trying to avoid.

This walkthrough uses [hexvero](https://github.com/maximilianfeix/hexvero), which reads both
archives statically and compares what they expose. Everything below is reproducible; the example
app is in the repository.

## 1. Two builds

```bash
npx hexvero demo
```

`demo` copies `notesdesk-1.4.0.asar` and `notesdesk-1.5.0.asar` into `./hexvero-demo`. They were
generated by `scripts/build-examples.mjs`; nothing in them comes from a real product.

## 2. What a page can reach

In Electron, a page reaches the main process through the preload script: `contextBridge`
exposes members, each sends on an IPC channel, and `ipcMain.handle` answers it. hexvero joins the
three into an `interfaces` list. Between the two builds:

```text
interfaces (2)
  + preload.js::notesdesk::checkUpdate  @ b: preload.js:9, handler main.js:30 · link direct
  - preload.js::notesdesk::openInShell  @ a: preload.js:9, handler main.js:30 · link direct
```

1.4.0 let a page open a path in the system shell through `openInShell`; 1.5.0 removes that and
adds `checkUpdate`, whose handler at `main.js:30` fetches
`https://updates.notesdesk.example/latest.json`. `link direct` means the member and the handler
use the same literal channel.

## 3. What a window may do

```text
windows (1)
  ~ main.js::win  @ b: main.js:8
      nodeIntegration: true → false, nodeIntegrationInEffect: "on" → "off", sandbox: false → true
```

Settings are reported as written. Where a value is not written and rests on Electron's default
for the version in `package.json`, hexvero says `default on` / `default off` instead of
pretending it was read.

## 4. What it could not tell

```text
Not established
  ! b: 1 IPC call(s) pass a channel that is not a literal or a constant that could be followed
    (a parameter, a computed value). … ipcMain.handle at main.js:33. (ipc_channel_unresolved)
```

1.5.0 registers `plugin:${name}` channels for names read from an environment variable. No static
reading can list them, so hexvero names the call and its line, and the IPC finding turns from
confirmed (`●`) to inferred (`○`). An unread file works the same way in a comparison: an item
there is `unknown`, not `removed`.

## 5. Check the evidence, write it down

```bash
npx hexvero ui --demo --open
npx hexvero compare hexvero-demo/notesdesk-1.4.0.asar hexvero-demo/notesdesk-1.5.0.asar --report report.md
```

In the UI every `file:line` opens the lines around it. The report is Markdown with the same rows,
the limitations of both sides and the command to reproduce it; the same inputs give the same
bytes. [An example report](https://maximilianfeix.github.io/hexvero/demo/).

## What this does not show

A static reading says what the code contains. It does not show that `checkUpdate` is ever
called, that the update URL is reachable, or that anything is exploitable. And it misses things:
on the newest blind set, an app written by someone without access to hexvero, it found 12 of 57
IPC channels and 5 of 8 changes between two versions, mostly because channels came from a
registry function it does not evaluate
([details](https://github.com/maximilianfeix/hexvero/blob/main/corpus/holdout4/README.md)). Treat
a list as what was found, not as everything there is.

## On your own app

```bash
npx hexvero compare old/MyApp.app/Contents/Resources/app.asar \
                    new/MyApp.app/Contents/Resources/app.asar --report report.md
```

Use it on software you own or are allowed to examine. If a fact is wrong or missing, a bug
report with the file (or a minimal reproduction) is the most useful thing you can send.
