# Security review (round 4, 2026-10-14)

Scope: everything that reads an untrusted target or a path chosen by an agent. That covers the
format parsers, the MCP tools that write files, the local UI server, `setup`, the engine adapters
and the caches. The review was done by reading the code and by trying the attacks against a
local build. It is not an external audit.

Status uses PASS / FAIL / BLOCKED / NOT RUN. "Fixed" means a change plus a regression test on
branch `oss/round-4`. Nothing has been released.

## Checked and found sound

- Recover path sanitizer: entries with absolute paths or `..` segments cannot leave the output directory.
- Engine adapters: arguments go as an argv array, never through a shell; addresses are checked
  against `ADDRESS_PATTERN`.
- UI server: per-session token, `Host` and `Origin` checks, loopback by default.
- Directory symlinks are not followed out of an opened directory.
- ASAR, ELF, Mach-O, PE, DEX and ZIP parsers survived a fuzz run with no crashes or hangs.
- `npm audit`: 0 known vulnerabilities in the dependency tree.

## Not covered

- No external penetration test.
- Windows-specific path handling (UNC paths, junctions) was not tested locally: BLOCKED (no
  Windows machine; CI runs the unit tests on Windows once the branch is pushed).
- Ghidra adapter: NOT RUN (Ghidra not installed).
