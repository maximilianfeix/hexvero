Built for the questions people actually ask

Which IPC channels can this Electron renderer reach? Is this binary stripped and PIE? Which Go modules shipped? What permissions does this APK take? hexvero answers from the bytes, with evidence, and never runs the target.

Zero dependencies

Every built-in parser is code in the repository. No JDK, no Python, no disassembler before the first useful answer.

Bounded by design

Every list is a page with offset, limit, a filter and a byte budget. The full result goes to a file, never into your context window.

Honest output

Findings are confirmed or inferred. Whatever was skipped, truncated or unreadable is listed as a limitation with a code.

Engines when you want them

radare2, rizin and Ghidra plug in behind one interface for disassembly and decompilation. hexvero never installs them for you.

12 MCP tools, not 139

The catalog stays under 32 KiB so small-context models keep working. Open, analyze, page, read bytes, export: it reads like a workflow.

  1. Register hexvero with Claude Code, Cursor, Windsurf, Gemini CLI, VS Code or Codex.
    npx hexvero setup --apply
  2. Ask a question about a file on your machine.
    Open ~/Downloads/app.asar with hexvero, list the IPC channels the renderer can reach
and tell me whether nodeIntegration is on.
  3. The agent pages through symbols, strings or modules and exports the full analysis when it needs everything.
    hexvero_collection { targetId, collection: "ipcChannels" }
hexvero_export { targetId, path: "./app.hexvero.json" }

A workbench, not a dashboard

hexvero ui starts a loopback server with a per-session token. Drop a file anywhere: verdict, fact sheet, hardening marks, findings with confidence, one tab per collection that exists, a hex viewer that decodes the selected byte in both byte orders, and a module graph for Electron apps. Dark and light, keyboard first, phone layout.
